# Acer 竖屏会议室门牌设计规范

更新：2026-09-30。适用于 Acer A312-2W（Android 14）上的 Fully Kiosk Browser，以及本仓库的 CreativeFitting Dotted-i 会议室门牌。安装位置现在要求屏幕竖置，因此新设计以竖屏、单列信息为准。这里的尺寸均为 **CSS 像素**。

## 方向与画布

Fully 横屏全屏曾实测为 **962 × 602 CSS px**，DPR 1.33；详见项目中的真机记录。设备转为竖屏后，Fully 全屏的准确可视尺寸还没有重新测量。首轮设计可暂用 **602 × 962 CSS px** 作为预览画布，这是把既有横屏尺寸旋转后的推算值，**不是已确认的竖屏实测值**。

| 测量项 | 结果 | 设计用途 |
| --- | --- | --- |
| Fully 横屏全屏 `window.innerWidth × innerHeight` | 962 × 602 CSS px，2026-09-29 实测 | 历史横屏基线；不要再作为本次竖屏稿的目标 |
| Fully 竖屏全屏布局视口 | 待 Acer 竖置后测量 | 确认前，首轮桌面稿暂用 602 × 962 CSS px |
| 先前 Android 浏览器竖屏报告 | 602 × 786 CSS px；旧版页面文档高 801 px | 历史参考；当时不是最终 Fully 全屏验收，不能代替当前测量 |
| DPR、visual viewport、安全区 | 竖屏待复测 | 用设备报告核对；不要按 DPR 推算面板原生分辨率 |
| 浏览器内核 | Android WebView / Chrome 113 | 新 CSS/JS 特性仍需在 Acer 上确认 |

现场复测时，把 Acer 竖置并在 Fully 全屏中打开门牌，再读取 `window.innerWidth × innerHeight`、`visualViewport`、DPR、方向和安全区。可通过部署维护者提供的公网诊断链接完成，不需要 ADB。**取得竖屏 Fully 报告后，应以实测 CSS 画布替换本页临时的 602 × 962 预览尺寸**，并更新 README、贡献说明和 Agent 规则。诊断链接中的测量码不放进公共仓库。

## 竖屏信息层级

- 采用单列从上到下排列，不把横屏左右双栏简单压窄。第一屏依次强调品牌与时间、会议室名称、当前状态、下一场预约起止时间。
- 当前状态和最近一场预约使用最大字号与主要色块；品牌、日期、同步时间等信息保持辅助层级。控制说明文字和装饰元素，保证墙外经过时也能迅速读到“哪间房、现在能否使用、下一场几点”。
- 主预约卡完整展示起止时间和“已预约”。后续预约只保留少量紧凑行，不能挤小当前状态或下一场时间。没有预约时明确写“暂无预约”。
- 房间名在窄宽度下可换行；预览长名称、容量、状态辅助文案与跨日时间，确保任何一个都不会压住主信息。
- 预留屏幕四边空白；不使用横向滚动、依赖 hover 的信息或会把主预约推到首屏之外的固定高度内容。
- 字号须按竖屏距离重新设定。现有横屏参考值（房间名 46px、状态 69px、主预约时间 43px）仅供层级参考，不是竖屏字号规范；最终要在 Acer 上以预期挂墙距离验读。
- 保留 CreativeFitting Dotted-i 字标和仓库 `assets/` 内字体授权。保持单文件部署，不使用运行时 CDN 或外部框架依赖。

## 数据与状态颜色

状态由飞书只读预约时段与当前时间决定。字标继续使用品牌蓝 `#1A85EC`。状态色与文案必须同时出现，不能仅靠颜色传达；接口失败、数据过期或房间停用都显示“状态未知”，不能显示空闲。

| 状态 | 状态卡底色 | 预约卡底色 |
| --- | --- | --- |
| 空闲 | 深绿 `#087F5B` | 浅蓝 `#EAF4FF` |
| 使用中 | 红色 `#B52E40` | 浅红 `#FDECF0` |
| 即将开始（10 分钟内） | 琥珀色 `#955D00` | 浅琥珀 `#FFF3D6` |
| 状态未知 | 灰蓝 `#4B5C70` | 白色，不显示过期预约 |

当前公开接口只有房间资料和预约起止时间，预约行显示 **“已预约”**。不要在页面或模拟数据中加入真实姓名、会议主题、内部 ID、飞书凭据或真实预约记录。原有六张横屏色彩预览（[空闲无预约](previews/available.png)、[空闲有预约](previews/next.png)、[使用中](previews/busy.png)、[即将开始](previews/soon.png)、[状态未知](previews/unknown.png)、[长房间名](previews/long.png)）仅供核对配色与品牌，不代表竖屏排版样例。

## 设计与验收

1. 启动 `python3 scripts/dev_server.py`，打开 `http://127.0.0.1:8767/preview/`，检查六种虚构数据状态：无预约、后续预约、使用中、即将开始、同步失败、长房间名和多场预约。
2. 首轮桌面稿暂按 **602 × 962 CSS px、DPR 1.33** 预览，注明这是推算尺寸。检查单列层级、首屏可见性、无水平/垂直滚动、时间完整和文字对比度；提交 PR 时附竖屏状态截图，并标出所用尺寸。
3. Acer 竖置后，在 Fully 全屏读取实际视口。按该实测尺寸重新检查六种状态，并在墙上预期观看距离确认房间名、状态和下一场时间清晰。桌面模拟和先前横屏测试都不能替代这一步。
4. 运行 `python3 scripts/build.py`、`python3 -m unittest discover -s tests -v`、`node --check src/app.js`。GitHub 合并不会自动更新 CA1；门牌页面由部署维护者另行审阅和发布。

2026-09-29 的六状态横屏检查结果只作为配色和历史回归记录，不能证明新竖屏版已在 Fully 上通过。当前网页仍需设计师按本规范另行调整竖屏排版，设备实测尺寸收到后再确立最终像素验收画布。

# Acer 横屏门牌设计规范

更新：2026-09-29。适用于 Acer A312-2W（Android 14）上的 Fully Kiosk Browser，以及本仓库的 CreativeFitting Dotted-i 会议室门牌。这里的尺寸均为 **CSS 像素**，供网页布局与设计稿使用。

## 真机画布

用户在最终横屏、隐藏地址栏的 Fully 页面打开公网诊断页后，CA1 于 2026-09-29 10:46（新加坡时间）收到以下结果；现场照片上的蓝色数字与报告一致。

| 测量项 | 结果 | 设计用途 |
| --- | --- | --- |
| `window.innerWidth × innerHeight` | **962 × 602 CSS px** | **主设计画布**，也是全屏验收尺寸 |
| `visualViewport.width × height` | 约 **962.25 × 601.69 CSS px**，缩放 1 | 核对真正可见区域；允许小数取整差异 |
| `screen.width × height` | 962 × 601 CSS px | 浏览器报告的屏幕尺寸；不要用它覆盖布局视口 |
| `devicePixelRatio` | 1.33 | 用于检查位图清晰度；不是 CSS 缩放倍数 |
| 方向与安全区 | `landscape-primary`、90°；四边安全区均为 0 | 按横屏设计，同时保留内容边距 |
| 浏览器内核 | Android WebView / Chrome 113 | 新 CSS/JS 特性需在 Acer 上复核 |

普通 Android 浏览器先前测得 **962 × 425 CSS px**。它是次要兼容画布：Fully 全屏正常使用时以 962 × 602 为准，但预览和 PR 仍要检查 962 × 425，以免退出沉浸模式或出现浏览器栏时裁切。不要按 `962 × 602 × DPR` 反推并宣称面板原生像素。诊断页自己的文档高 987px、可以滚动；这个数字**不代表门牌页面被裁切**。

## 设计与数据要求

- 第一眼能读到 **会议室名称、当前状态、下一场预约的起止时间**。这是挂在墙上的指示屏；减少段落和装饰性文字，让状态和时间占据主要视觉位置。
- 在 962 × 602 和 962 × 425 都不要出现横向或纵向滚动；房间名、状态、下一场时间和必要的异常提示必须完整可见。使用响应式布局和当前页面的可视高度处理方式，不要把 602px 写成唯一固定高度。预留实体边框可能遮挡的四周边距。
- 当前实现的参考字号约为：房间名 **46px**、状态 **69px**、主要预约时间 **43px**、预约说明 **19px**。这组字号曾在较矮的 Acer 视口通过布局检查；新设计可以调整，但若缩小关键信息，须在平板实际挂墙观看距离复核可读性。
- 使用 Dotted-i 字标及仓库 `assets/` 中的授权字体；样式变量与当前用法见 `src/styles.css`。网页应保持单文件可部署、无运行时 CDN 或框架依赖；不要依赖 hover 才能看到信息。
- 明确展示空闲、使用中、即将开始、状态未知。颜色不能代替文字。数据失败、过期或房间停用时必须显示“状态未知 / 请查看飞书”，不能沿用绿色空闲。
- 公开接口目前只有房间资料和预约的开始/结束时间；预约显示 **“已预约”**。不要在页面或模拟数据中加入真实姓名、会议主题、内部 ID、飞书凭据或真实预约记录。最多展示少量后续预约，确保主信息不会被次要列表挤走。

## 设计师验收

1. 运行 `python3 scripts/dev_server.py`，打开 `http://127.0.0.1:8767/preview/`。六个状态依次检查：无预约、后续预约、使用中、即将开始、同步失败、长房间名与多场预约；它们全部使用虚构数据。
2. 在浏览器开发工具中分别设置 **962 × 602** 和 **962 × 425 CSS px**、DPR 1.33，确认无页面滚动、卡片内部无遮挡，长名字和最长时间段仍可读。提交 PR 时附受影响状态在两个尺寸下的截图，并说明文字层级与留白。
3. 运行 `python3 scripts/build.py`、`python3 -m unittest discover -s tests -v`、`node --check src/app.js`。合并前再用 Acer 的 Fully 打开候选页，确认全屏、远距阅读与实际页面无裁切；桌面模拟不能代替 Android WebView 真机验收。

2026-09-29 的现有 UI 基线已在桌面 Chromium 模拟的六个状态、两个视口下检查：页面文档宽高等于视口，页脚与最后一条预约均未越出容器。这是布局回归基线，不是对未来设计或真实 Fully 门牌渲染的自动保证。GitHub 合并不会自动更新 CA1；发布仍由部署维护者单独执行。
